# SuperBizAgent 渐进式学习设计

**目标：** 让已有 Java CRUD 经验的学习者，能独立解释、修改、排查并复现本项目的核心 AI 运维能力。

## 学习约束

- 每次学习约 15 分钟，分多次完成。
- 使用中文和朴素表达；首次出现的术语必须解释。
- 不要求先记住全部细节。每一节只处理一个可验证的问题。
- 不做无目的的命令复制；运行命令前必须说明它解决的问题、关键参数和预期现象。
- 学习者已有 Controller、Service、增删查改接口的实践经验，但 Java/Spring Boot 基础仍需在遇到时补齐。

## 采用的学习方式

采用“运行现象 → 对应代码 → 自己复述”的方式，而非按目录从头阅读。

每节课固定为四段：

1. 约 3 分钟：说明本节只要回答的一个问题，并回顾上一节。
2. 约 7 分钟：观察一个运行现象或阅读 2 到 4 个直接相关文件。
3. 约 3 分钟：用人话把调用链和职责串起来。
4. 约 2 分钟：由学习者完成一句复述、一次预测或一个很小的改动设计。

运行环境关闭时，课程继续进行：先阅读静态代码、配置和调用链；只有在需要验证实际行为时才安排启动。

## 阶段路线

### 1. 项目地图

学习者能解释网页、Controller、Service、AI 模型、Milvus 向量数据库和运维文档库的职责，以及它们之间的关系。

第一节主题是“一次提问如何在项目中旅行”。

### 2. 普通聊天

从网页请求追踪到 `ChatController` 和 `ChatService`，理解 HTTP 请求、会话 ID、流式与非流式响应，以及大模型调用在服务层的位置。

### 3. RAG 与运维文档

理解上传文档、文本分块、向量化和相似度检索。阅读 `InternalDocsTools`，明确它是 Agent 获取内部资料的工具，而不是模型本身的记忆。

### 4. Agent 工具调用

阅读日期时间、日志查询和指标查询工具。理解工具的方法描述为何重要、模型怎样选择工具、Java 方法如何向 Agent 返回可用信息。

### 5. AIOps Agent

理解告警处理的计划、执行、再计划和生成报告流程；追踪 AIOps 请求从接口进入到 Agent 的整个调用链。

### 6. 学习者主导实践

独立提出并完成一个小而完整的改动，例如新增一个受控的运维查询工具或扩展一个 API；能说明它的职责、依赖、风险和测试方式。

## 学习完成标准

学习者可以：

- 画出并口头讲清核心请求链路。
- 找到并解释关键文件的职责，而不把所有逻辑都塞进 Controller。
- 解释 RAG、向量数据库和工具调用在项目中的实际作用与边界。
- 在指导较少的情况下新增一个小功能、调试一个常见错误，并验证结果。
- 以项目作者的角度说明主要设计选择和可改进之处。

## 边界

本路线只覆盖当前仓库实现的功能；不会假定所有 AI Agent 产品都必须使用相同架构。涉及线上真实告警、凭据或生产数据时，先使用示例或脱敏数据。
